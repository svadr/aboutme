Engineering the workflow

I built a harness around my coding agent to turn it into a more reliable part of the development process. It helps me build real features and tools, including an agent that investigates data discrepancies directly from support tickets.

The system is built around three ideas:

  1. 01

    Context

    Give the agent a working understanding of the codebase, its architecture, and the decisions that aren’t obvious from reading the code alone.

  2. 02

    Constraints

    Enforce engineering rules through hooks and automated checks. Risky changes get blocked, and code gets linted as it’s written rather than after the damage is done.

  3. 03

    Verification

    Writing code is only one step. Tests, end-to-end journeys, independent verification, and code review help establish whether a change actually works.

From ticket to production

  1. Ticket
  2. Spec
  3. Implementation
  4. Tests
  5. Verification
  6. Review
  7. Ship

The goal isn’t to generate more code. It’s to shorten the distance between identifying a problem and delivering a reliable solution.

I’m interested in systems that get better with every iteration: software that is easier to maintain, workflows that eliminate unnecessary work, and AI agents that can take on more responsibility without sacrificing engineering standards.
